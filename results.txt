# AI Usage Log

This project was developed with substantial assistance from Claude (Anthropic), used
interactively across a single extended conversation covering the full assignment (Q1-Q5).
This log summarizes the workflow, the AI's role at each stage, and how AI-generated code was
verified.

## Tool Used
Claude (Anthropic), web-based chat interface. All code was generated in response to natural-
language prompts, then copied into the local project, run by the developer, and iterated on
based on real command output/errors pasted back into the conversation.

## Workflow Pattern

The general pattern throughout was:
1. Developer describes the assignment requirement or a problem encountered (e.g. an error
   message, unexpected output, a slow-running script).
2. Claude proposes code and/or a diagnosis, with reasoning for *why* (e.g. explaining BM25's
   TF-saturation term, or why a leakage-filtering bug caused `click_history=0` for the MIND
   train split).
3. Developer runs the code locally, pastes back real output (including errors).
4. Claude iterates based on real results — this repo's code went through several rounds of
   genuine bug fixes based on actual run output, not just first-draft code.

## Notable Debugging Episodes (real bugs caught via human-in-the-loop testing)

1. **Leakage-filtering bug**: an early version of `split.py` used a single per-user global
   cutoff for filtering click history, which produced 0 valid history rows for the MIND train
   split. Caught because the developer reported the anomalous `0` in real output; fixed by
   redesigning to dynamic per-impression filtering in `feature_store.py`.
2. **BM25 performance**: `rank_bm25`'s pure-Python scoring made the evaluation script
   effectively hang at MIND's scale (51k articles × thousands of queries). Diagnosed from a
   `KeyboardInterrupt` traceback the developer provided; fixed by switching to the vectorized
   `bm25s` library with batched retrieval.
3. **EB-NeRD submission script memory issue**: loading all 13.5M test behavior rows into
   memory at once (twice — once for a schema check, once for processing) caused the developer's
   laptop to hang. Fixed by switching to `pyarrow`'s batch-streaming API.
4. **MIND test set scope**: developer discovered (by downloading and inspecting) that
   MINDsmall has no official test split — only MINDlarge does — which meant the submission
   pipeline needed its own freshly-built index over MINDlarge_test's article set rather than
   reusing the MINDsmall-trained index.

## Human Contributions

- All commands were actually executed by the developer, on their own machine, against real
  downloaded data — no code or result in this repo is unverified/untested.
- All external service interactions (Kaggle registration, HuggingFace token creation, Codabench
  registration and submission) were performed manually by the developer.
- Final submission file review (checking rank counts matched permutations, format spot-checks
  against the official sample submission) was done by the developer before each Codabench upload.
- All error messages, unexpected outputs, and anomalies included in this log were identified by
  the developer running real code, not anticipated in advance by the AI.
